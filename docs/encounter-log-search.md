# Encounter log search and copy contract

The decompiled ACT `FormEncounterLogs` keeps an ordered copy of encounter log entries. Text search uppercases the search text and each line using the current .NET culture, then marks matching entries; an empty query matches every entry. Regex search uses .NET `RegexOptions.IgnoreCase`. Search resets the cursor. Next and previous scan without wrapping. The result-only view preserves the search-result order and selection refers to the visible view. Copy Results uses all marked source entries; Copy All uses every source entry; Copy Selection uses selected visible entries; Copy Combat includes entries whose type is neither 0 nor -1. Copy operations append `Environment.NewLine` per row. These observations are from decompiled ACT code, not native-form execution.

The `aftercast::log_search` library now provides bounded in-memory text matching, adjacent-match navigation and copy-text construction over caller-owned ordered rows and stable indices. The caller maps result-only selections back to source indices. The caller supplies the newline, and output is limited to 16 MiB. Rust Unicode uppercasing is culture-independent and can differ from ACT current-culture casing. No clipboard is accessed. The log window explicitly captures a log-only owned snapshot, reads its pages under the same revision, and offers .NET text or regex search, a type filter, result highlighting, result-only display, next/previous navigation, page selection and memory-only text preparation. Searches use the original .NET current-culture text and regex semantics with 25 ms per regex match, a two-second overall scan check and a 16 MiB input bound; regex construction itself is not preempted. Invalid patterns and timeout errors are visible. The window limits captured text to 16 MiB and indicates dropped logs; an in-progress or partial import can be incomplete. A later action/log snapshot capture invalidates the worker handle, and the window reports that error on the next search. Cancel retires the controller result but does not forcibly abort a running managed regex. Prepared text is never sent to the operating-system clipboard. Native GUI interactions and Windows execution remain unverified.
