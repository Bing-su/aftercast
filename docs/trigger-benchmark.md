# Trigger benchmark contract

Decompiled ACT `FormCustomTriggerBenchmark` requires a selected encounter with more than 1,000 log entries. It measures the compiled baseline `.*?.*?` against every retained line starting at `TimeStampLen`, followed by each registered trigger's existing compiled `RegEx`. It displays elapsed whole milliseconds and a ratio to baseline. It does not invoke trigger matching effects. These findings are from the ACT implementation; its native form has not been executed here.

Aftercast measures 1–32 explicitly selected registered trigger keys against an owned log snapshot. It uses each trigger's compiled expression, including ACT's distinction between the compiled expression and a later edit to the visible regex string. It records the encounter's retained line count, omitted count, timestamp length, baseline time, trigger time and match count; it does not run parser, audio, TTS, timers, external notifications or trigger result callbacks. Selection and revision must remain valid; a changed log or trigger snapshot is an error. A line shorter than the timestamp offset is an explicit error.

Aftercast bounds the input to 65,536 retained lines and 16 MiB, and checks a two-second total budget before each match and after each expression. Existing trigger expressions have a 100 ms per-match timeout; timeout and invalid definitions surface as errors. These safeguards differ from ACT's unbounded native benchmark. A running managed match is not forcibly interrupted by the UI Cancel button: cancellation retires the result and the match finishes or times out. The owner worker is occupied while measuring. The result is a diagnostic, not an exact prediction of live trigger latency. When baseline rounds to zero milliseconds, aftercast displays the ratio as unavailable rather than displaying ACT's floating-point infinity or NaN.

The UI selects an encounter from the existing Analysis selection and triggers from the existing paged trigger catalog, up to 32. A newly captured log snapshot can invalidate another action/log snapshot; stale requests are rejected. Actual native controls and Windows timing remain unverified, as does independent review (quota pending).
