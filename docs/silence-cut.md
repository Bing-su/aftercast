# Encounter silence cut

The [ACT 3.5.0.273 release notes](https://advancedcombattracker.com/version.php) describe Encounter Silence Trimming. ACT 3.8.5.288's `Options_MainTableGen` labels this “Number of seconds to wait after the last combat action to pause the encounter duration”. The checkbox defaults off; its numeric control defaults to 6 seconds and accepts 1–60. `CheckIdleCutSilence` compares the supplied `SetEncounter` time with the previous accepted call: only a strictly greater gap adds the prior encounter end to `EndTimes` and the new call time to `StartTimes`. It mirrors those boundaries to the zone's `All` encounter. The existing segment duration machinery adds the active intervals, so duration-dependent rates use that total. This option does not itself end a fight and is independent of the idle-end options.

Aftercast captures the policy at host startup and applies it to live and import parsing. Earlier admitted actions drain before the previous end time is read, avoiding a stale boundary caused by the asynchronous action queue. This is a scheduling difference from the decompiled ACT implementation; native ACT thread timing has not been compared. Empty segments and plugin-edited lists retain existing duration behavior. Private history and encounter XML retain the segment lists. Synthetic managed and worker tests cover boundaries, multiple segments, damage/healing rates, import, restart, and history restoration; no live game data or native GUI was used.
