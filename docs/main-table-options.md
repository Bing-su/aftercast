# Main table options

ACT 3.8.5.288's `Options_MainTableGen` defaults to a 5-second update period (0 disables periodic grid updates; the control permits 0–60), thousand separators enabled and reverse sorting enabled. Its main table receives the reverse operation for combatant, attack and swing lists, not the zone encounter list or category list. Its built-in display callbacks use `ActGlobals.mainTableShowCommas`; plugins may use that global themselves. Arbitrary plugin cell text is not rewritten.

Aftercast persists the refresh period and direction in UI settings and sends the comma setting at worker start. A pane-owned refresh clock preserves page offsets and uses request generations to retire late results on navigation or session replacement; delayed ticks coalesce. With no registered columns the retained encounter list is refreshed instead. Period 0 disables this clock. ACT schedules from its global one-second UI timer, so phase and scheduling under a busy UI can differ.

The main table uses the ACT default callbacks `eDSort=EncDPS`, `mDSort=Damage` and `aTSort=Time` when no sort is chosen, followed by its damage or time fallback. An explicitly selected comparison keeps the original plugin callback and the same fallback. The shared direction applies to combatant, attack and action tables. Main ordering uses .NET `Array.Sort` followed by reverse, matching an executable ACT-object fixture including 24 equal rows under the .NET 10 reference runner. Native Windows/.NET Framework ordering and plugin callback timing remain unverified; callback consistency checks and a fixed comparison budget intentionally remain in force. Unlike ACT's header click, the editor does not mutate the plugin-visible global sort keys.

ACT's `Options_TableZone` is a checked, ordered list of `EncounterData.ColumnDefs` displayed when a zone is selected, not a separate registry of zone columns. Aftercast's existing encounter-level editor persists those same registration keys, order and visibility. Selecting a retained encounter and choosing its Zone filters both the main table and sidebar to the actual owning `ZoneList` object, even when names coincide; the anchor is session-owned and removal is reported. The existing tree's empty zones cannot yet be selected because the UI uses a retained encounter as its anchor. Native tree appearance and interaction remain unverified. No extra zone column registry is introduced.
